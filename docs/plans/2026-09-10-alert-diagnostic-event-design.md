# 指标异常到告警事件最小闭环设计

## 目标

把已有 Web Vitals 聚合与精准诊断连接为一个稳定的领域输出：指标异常时生成带诊断证据的告警事件。本阶段不包含通知渠道、后台调度、规则配置和告警生命周期持久化。

## 方案

提供 `GET /api/v2/alerts/evaluate`。接口对同一时间范围并行查询 LCP、CLS、INP 的 P75 与精准诊断结果。每个指标至少需要 10 个样本；超过 Core Web Vitals 的良好阈值时生成一个 `triggered` 事件：LCP 2500ms、CLS 0.1、INP 200ms。

告警事件包含稳定的规则 ID/版本、应用、指标定义、观察值、阈值、样本数、时间范围、生成时间，以及同时间范围的版本化诊断 findings。诊断证据不足不会阻止指标告警，只会得到空 findings 和明确的诊断样本数量。

## 边界

- 内置三条只读规则，不提供增删改。
- 按需评估，不做定时任务。
- 不写告警表，不处理确认、静默、恢复和去重。
- 不发送 Webhook、邮件或其他通知。
- 时间范围默认 24 小时，最大 30 天，与指标查询保持一致。

## 验收

1. 正常指标不生成事件，样本不足不生成事件。
2. 异常指标生成包含阈值、观察值和规则版本的事件。
3. 精准诊断 finding 被附加到对应事件。
4. 参数错误返回 400，任一存储查询失败返回 503。
