# 开源多端性能监控与异常诊断平台 PRD

- **文档状态**：草案
- **当前开发版本**：v0.2（Web Vitals、采样与实验性内存）
- **目标版本**：MVP 1.0（完整 Web 性能平台）
- **首版平台**：Web
- **目标用户**：个人开发者、中小型研发团队、开源贡献者
- **关联设计**：[总体架构设计](../plans/2026-08-23-open-performance-platform-design.md)

## 1. 产品概述

### 1.1 背景

前端性能问题通常发生在真实用户、特定版本、设备和网络环境中，单靠开发环境难以复现。现有商业平台可能存在费用、数据出境、定制困难或部署复杂等问题。

本项目提供一套可自托管的开源性能监控与异常诊断平台，通过 SDK 自动采集真实用户数据，在统一控制台完成趋势观察、问题定位、告警和修复验证。

### 1.2 产品定位

产品长期支持 Web、小程序、移动 App 和桌面应用；MVP 只交付 Web 全链路能力，但事件协议和服务端从首版起支持多端扩展。

产品由以下部分组成：

```text
多端 SDK → 数据接入与质量处理 → 数据计算与诊断
       → 管理控制台 → 告警通知 → 文档与接入 Demo
```

### 1.3 产品目标

- 用户能在 30 分钟内完成自托管部署并登录平台。
- 用户能在 15 分钟内完成 Web SDK 接入并看到首条有效数据。
- 平台能回答：是否变慢、是否卡顿、内存是否溢出、影响谁、从哪个版本开始、可能原因是什么。
- 数据异常、SDK 失败或平台不可用时，不影响被监控业务正常运行。
- 建立稳定的事件协议和插件机制，为后续多端 SDK 与社区扩展打基础。

### 1.4 非目标

MVP 不包含：

- 小程序、iOS、Android、Flutter 和原生桌面 SDK 的正式交付。
- 商业 SaaS 计费、套餐、配额售卖和复杂租户隔离。
- Kubernetes、多地域容灾和超大规模集群的默认部署。
- 录屏回放、用户输入采集和完整请求/响应正文采集。
- 通过不可解释的 AI 评分代替有证据的数据诊断。

## 2. 目标用户与场景

### 2.1 用户角色

| 角色 | 主要诉求 |
|---|---|
| 平台管理员 | 部署平台、管理团队、安全和数据保留策略 |
| 团队管理员 | 管理成员、项目、通知渠道和权限 |
| 前端开发者 | 接入 SDK、观察性能、定位版本与页面问题 |
| 测试/质量人员 | 验证版本质量、复现异常、检查性能回归 |
| 技术负责人 | 关注整体趋势、影响范围、告警和治理进展 |
| 只读成员 | 查看被授权项目的数据与诊断结果 |
| 开源贡献者 | 开发插件、框架适配器、指标和平台 SDK |

### 2.2 核心使用场景

1. 新团队通过 Docker Compose 部署平台并创建管理员账号。
2. 开发者创建 Web 应用，复制配置，安装 SDK 并验证接入。
3. 负责人查看秒开率、首屏、Web Vitals、卡顿和异常趋势。
4. 版本发布后，通过版本对比识别性能回退。
5. 收到卡顿或异常告警后，下钻到页面、设备、网络、版本和会话。
6. 用户查看诊断证据和排查建议，修复后验证指标是否恢复。
7. 团队开发自定义插件，监控登录、下单等业务链路。

## 3. 产品原则

- **业务安全优先**：SDK 不能阻塞页面，也不能将自身异常抛给业务。
- **数据可信优先**：明确有效分母、缺失、推导、丢弃和采样影响。
- **证据优先**：诊断必须展示数据证据、影响范围和建议。
- **渐进接入**：默认配置即可运行，高级能力按需开启。
- **隐私默认保护**：默认最小采集，敏感字段必须显式白名单授权。
- **平台统一、终端独立**：共享事件语义和服务端，各终端独立实现 SDK。

## 4. MVP 范围与优先级

### 4.1 当前开发基线：v0.2

v0.2 在 FP/FCP 最小闭环上扩展 Web Vitals、采样和实验性内存监控。

| 模块 | v0.2 功能 |
|---|---|
| 使用模式 | 单应用、免登录，通过环境变量配置固定 `appId` |
| Web SDK | 采集 FP、FCP、LCP、CLS、INP 和可用的 JS 堆内存，支持会话采样与批量上报 |
| 服务端 | 接收 V1/V2 事件，校验、持久化并提供 Paint、通用指标和内存健康查询 |
| 数据存储 | PostgreSQL 保存通用指标明细，执行时间聚合、分位数查询和内存快照关联 |
| Console | 展示 Web Vitals 等级、摘要、通用趋势、内存指标和健康风险状态 |
| Demo | 提供布局偏移、慢交互和完整 Browser SDK 接入示例 |
| 部署 | Docker Compose 启动 PostgreSQL、API 和 Console |

v0.2 不包含登录、团队、成员、RBAC、项目管理、Redis、ClickHouse、独立接入网关、异常采集、外部告警和多端 SDK。

v0.2 的发布验收标准：

1. Docker Compose 可以启动完整环境，Console 无需登录即可访问。
2. Demo 接入 SDK 后，Paint、Web Vital 和可用的内存事件可以写入 PostgreSQL。
3. 非法指标、非有限数值、负数和缺少必要字段的事件被拒绝或丢弃。
4. 查询 API 返回各指标的样本量、平均值、P50、P75、P90 和时间序列。
5. Console 展示全部指标、等级、趋势和内存状态，并正确处理无数据、加载和失败状态。
6. SDK 或平台不可用时不影响 Demo 的页面功能。

## 6. 核心用户流程

### 6.1 首次部署与登录

```text
运行 Docker Compose → 健康检查 → 创建初始管理员
→ 登录 → 创建团队 → 进入空项目引导
```

### 6.2 应用接入

```text
创建项目 → 创建 Web 应用 → 选择原生/Vue 接入方式
→ 复制 SDK 配置 → 在业务发布 → 发送验证事件
→ 平台验证协议和数据 → 展示首条数据或具体失败原因
```

### 6.3 问题处理

```text
收到告警 → 查看指标趋势和影响范围 → 按版本/页面/设备下钻
→ 查看慢资源、长任务或异常证据 → 修复发布
→ 对比修复版本 → 指标恢复 → 告警恢复
```

## 7. 功能需求

### 7.1 账号、团队与权限

#### FR-AUTH-01 登录与会话（P0）

- 支持账号密码登录、主动退出和刷新登录状态。
- 连续失败达到阈值后进行短时限制，不泄露账号是否存在。
- 管理员可禁用成员；禁用后现有会话应失效。

#### FR-TEAM-01 团队与成员（P1）

- 用户可创建和切换团队。
- 团队管理员可邀请、移除成员并调整角色。
- 角色至少包含：管理员、维护者、开发者、只读成员。
- 所有资源查询必须受团队和项目权限约束。

### 7.2 项目与应用管理

#### FR-PROJECT-01 创建项目和应用（P0）

- 项目用于组织相关应用；应用对应一个可独立接入和分析的终端程序。
- MVP 应用类型只开放 Web，界面保留后续平台类型。
- 应用字段至少包含名称、应用标识、生产/测试环境、时区和数据保留期。
- 应用标识生成后不可修改，显示名称可以修改。

#### FR-PROJECT-02 上报密钥与来源（P0）

- 创建应用后生成仅用于数据上报的公钥。
- 支持密钥轮换、停用和来源域名白名单。
- 管理权限和数据库凭据不得出现在 SDK 配置中。

#### FR-PROJECT-03 版本管理（P0）

- SDK 事件必须携带发布版本和环境。
- 控制台可查看版本首次出现时间、活跃会话和指标对比。
- 未提供版本的事件标记为 `unknown`，并提示完善接入配置。

### 7.3 SDK 接入与配置

#### FR-SDK-01 Web SDK（P0）

- 提供 ESM、CJS 和 CDN 构建产物。
- 提供原生 JavaScript/TypeScript 接入和 Vue `app.use()` 接入。
- Core 不依赖前端框架；框架包只处理路由、生命周期和框架错误。
- 支持初始化、用户/标签设置、插件、自定义上报和销毁。
- 重复初始化不能重复安装监听器；销毁后还原被包装的浏览器 API。

#### FR-SDK-02 SDK 可靠性（P0）

- SDK 自身异常全部隔离，不得向业务冒泡。
- 支持采样、本地有界缓冲、批量上报、失败退避和过期丢弃。
- 上报请求不得被 SDK 自己再次采集。
- 页面退出时优先使用 Beacon，按能力降级。

#### FR-SDK-03 插件和业务监控（P1）

- 插件拥有明确的安装、启动、停止和销毁生命周期。
- 支持自定义事件、计数、计时和 Span。
- 自定义字段受大小、数量、命名和隐私规则约束。

### 7.4 性能与异常采集

#### FR-COLLECT-01 页面性能（P0）

- 采集导航、首屏、LCP、CLS、INP 等支持的页面指标。
- 按能力检测决定是否采集；不支持时标记 `unavailable`，不能写入 `0`。
- 秒开阈值可按项目配置，默认值由指标口径文档确定。

#### FR-COLLECT-02 卡顿与资源（P0）

- 采集 Long Task、静态资源加载耗时与失败。
- Long Tasks 不支持时允许降级估算，但估算值必须标记来源和可信度。
- 支持按页面、资源域名、资源类型、版本和设备分析。

#### FR-COLLECT-03 网络请求（P0）

- 采集 fetch/XHR 的方法、清洗后的 URL、耗时、状态码和错误类型。
- 默认不读取请求正文、响应正文、Cookie 和认证 Header。
- 包装行为不得改变原请求参数、返回值、流、异常和取消行为。
- 慢请求默认阈值为 1,000 ms，支持按接口匹配规则覆盖。

#### FR-COLLECT-04 异常（P0）

- 采集 JavaScript Error、未处理 Promise、资源加载和接口异常。
- 相同错误按稳定指纹聚合，同时保留样本和影响用户/会话数。
- Source Map 堆栈还原属于 P1。

#### FR-COLLECT-05 内存（P0，实验性）

- 在运行环境支持时采集内存当前值、上限和增长趋势。
- 不支持时明确说明，不将 Web 内存数据作为跨浏览器 SLA。
- 项目可配置内存阈值和持续窗口。

### 7.5 数据接入与质量

#### FR-INGEST-01 接入限流（P0）

- 按项目令牌桶限流，并叠加 IP/设备保护阈值。
- 限制单批事件数、单事件和请求总体积。
- 超限返回 HTTP 429 与 `Retry-After`；SDK 指数退避。
- 限流规则可配置，Redis 故障时启用有界本地保护策略。

#### FR-DQ-01 校验、推导与丢弃（P0）

处理顺序必须固定：

```text
Schema 校验 → 类型/范围校验 → 无效识别 → 缺失推导
→ 标准化 → 隐私清洗 → 去重 → 标准事件
```

- 必要字段有效：接收。
- 必要字段缺失但可以精确推导：记录规则和 `exact` 后接收。
- 只能近似推导：记录 `estimated`，默认不进入核心 SLA。
- 必要字段无法推导：丢弃。
- 非必要指标无效：只丢弃该指标，不丢弃整条有效事件。
- 业务无效数据进入 discard；系统暂时失败进入 dead letter；暂不识别协议进入 quarantine。

#### FR-DQ-02 数据质量可观测（P0）

- 展示接收量、接收率、丢弃率、推导成功率、死信量、隔离量和积压。
- 丢弃原因至少按应用、平台、事件类型和原因聚合。
- 丢弃日志不得包含原始敏感数据。
- 管理员可查看死信并执行受控重放；业务无效数据不可重放。

### 7.6 数据计算与统计

#### FR-COMPUTE-01 事件与会话计算（P0）

- 计算秒开、长任务、请求成功、内存越线和异常指纹。
- 关联同一页面访问中的启动、首屏、资源、卡顿和异常。
- 会话不完整时标记状态，并按指标规则决定是否进入分母。

#### FR-COMPUTE-02 窗口聚合（P0）

- 支持分钟、小时、天聚合。
- 支持计数、去重用户、去重会话、平均值及 P50/P75/P90/P99。
- 支持按应用、环境、版本、页面、设备、浏览器、系统、地区和网络维度分析。
- 计算规则必须定义事件时间、迟到/乱序窗口、时区、采样权重、有效分母和去重键。
- 聚合结果记录指标版本和规则版本，支持受控重算。

### 7.7 管理控制台

#### FR-CONSOLE-01 应用总览（P0）

- 默认展示最近 24 小时，可切换常用时间范围和自定义范围。
- 展示活跃用户/会话、秒开率、首屏、Web Vitals、卡顿、请求成功率和异常趋势。
- 每个指标显示当前值、趋势、有效样本量和与上一周期的变化。
- 无数据时显示接入引导；数据不足时不能误报趋势结论。

#### FR-CONSOLE-02 下钻分析（P0）

- 从总览进入页面、卡顿、网络、资源和异常详情。
- 支持版本、页面、设备、浏览器、系统和网络筛选。
- 图表必须说明指标口径、时间范围、单位和样本量。
- 筛选条件应体现在 URL 中，便于分享和复现。

#### FR-CONSOLE-03 数据状态（P0）

所有数据页面都必须支持加载、空数据、部分数据、无权限、查询失败和数据延迟状态，不能用空图表代替错误提示。

### 7.8 问题诊断

#### FR-DIAG-01 诊断结果（P0）

诊断必须按照以下结构呈现：

```text
现象 → 影响范围 → 首次出现版本 → 相关维度
→ 证据 → 可能原因 → 可执行建议
```

- 首版支持版本性能回归、慢资源、长任务集中、弱网退化和异常指纹诊断。
- 每项结论显示使用的指标、样本量、时间范围和规则版本。
- 样本量不足或相关性不充分时，应明确说明不确定性。

### 7.9 告警中心

#### FR-ALERT-01 告警规则（P0）

- 支持指标/事件、阈值、比较符、持续窗口、最小样本量和筛选维度。
- 支持启用、停用、复制、编辑和删除规则。
- 保存前提供规则摘要，避免用户误解触发条件。

#### FR-ALERT-02 告警生命周期（P0）

- 支持连续窗口、防抖、合并、静默、频率限制和恢复通知。
- 告警状态至少包含正常、触发、已确认、已静默和已恢复。
- 通知内容包含应用、环境、指标、当前值、阈值、影响范围和详情链接。

#### FR-ALERT-03 通知渠道（P0）

- MVP 支持 Webhook 和邮件。
- 支持发送测试通知、失败重试和失败记录。
- 飞书等平台通过通用 Webhook 接入。

### 7.10 文档与 Demo

#### FR-DOC-01 文档站（P0）

必须包含快速开始、Docker Compose 部署、SDK 接入、配置、指标口径、兼容矩阵、插件开发、隐私、安全、升级迁移、告警和异常帮助。

#### FR-DEMO-01 故障 Demo（P0）

Demo 可主动制造慢首屏、长任务、内存增长、慢接口、资源失败、JS 异常和版本回归，并覆盖“制造问题—接收数据—看板分析—触发告警—查看诊断”的闭环。

## 8. 权限矩阵

## 9. 数据与隐私规则

- 默认不采集输入值、Cookie、认证 Header、请求正文和响应正文。
- URL 查询参数、Header、用户字段和自定义字段采用白名单策略。
- 用户 ID 支持客户端或服务端哈希；未设置时使用匿名设备/会话标识。
- 支持应用级数据保留期、数据导出和删除。
- Source Map 和符号表是私有制品，只向授权成员开放。
- SDK 配置和文档必须说明采集范围及业务方的合规责任。

### 9.1 MVP 默认产品参数

| 参数 | 默认值 | 配置范围 |
|---|---:|---|
| 秒开阈值 | 1,000 ms | 应用级覆盖 |
| 长任务阈值 | 50 ms | 指标规则版本控制 |
| 严重卡顿阈值 | 200 ms | 应用级覆盖 |
| 慢请求阈值 | 1,000 ms | 应用级默认，支持接口规则覆盖 |
| 会话超时 | 30 分钟 | 应用级覆盖 |
| 迟到事件窗口 | 10 分钟 | 实例级配置 |
| 明细数据保留期 | 30 天 | 应用级覆盖 |
| 秒开率告警最小样本 | 每窗口 100 个有效页面访问 | 告警规则覆盖 |

接口规则按标准化后的请求方法和 URL 模式匹配，优先级高于应用默认值；未命中接口规则时回退到 1,000 ms。

## 10. 非功能需求

### 10.1 性能与规模

- 支持 10～50 个应用、日均不超过 100 万事件，峰值按平均值 5 倍设计。
- 接入网关单实例持续接收不少于 1,000 events/s，接收接口 p95 小于 100 ms。
- 常用 24 小时看板查询 p95 小于 2 秒。
- Web SDK Core 目标小于 20 KB gzip，平均 CPU 开销目标低于 1%。

### 10.2 可用性与恢复

- 单机部署目标可用性 99.5%。
- 默认备份策略下目标 RPO 24 小时、RTO 4 小时。
- 队列、数据库或通知服务失败时有积压、重试、死信和健康告警。

### 10.3 兼容性

- Web 首版支持现代 Chromium、Firefox 和 Safari 系浏览器。
- 使用能力检测和按指标降级，不按浏览器名称猜测能力。
- 支持 SPA、MPA、Hash/History 路由、iframe、SSR 安全加载和微前端。
- 详细版本范围由兼容矩阵和自动化测试结果维护。

### 10.4 可运维性

- 提供结构化日志、健康检查、Prometheus 指标和关键内部告警。
- 数据处理链路可查看吞吐、延迟、积压、丢弃、推导、死信和失败率。
- 默认明细数据保留 30 天，聚合数据可配置更长周期。

## 11. 产品成功指标

MVP 发布后重点观察：

| 指标 | 目标 |
|---|---|
| 首次部署成功率 | 按文档一次成功的用户占比持续提升 |
| 首次有效数据时间 | 中位数不超过 15 分钟 |
| SDK 对业务的严重影响 | 0 起事故 |
| 有效事件接收率 | 不低于 99%，排除主动采样和明确无效事件 |
| 告警时效 | 满足规则后 2 个计算窗口内发出 |
| 诊断可解释率 | 所有诊断均包含证据、样本量和规则版本 |
| 文档闭环率 | P0 功能均有接入、使用和异常帮助文档 |

这些目标需在真实开源用户反馈和容量测试后校准，不作为未经验证的商业承诺。

## 12. MVP 验收标准

MVP 满足以下条件方可发布：

1. 新用户能通过 Docker Compose 启动平台、创建管理员并登录。
2. 用户能创建 Web 应用，通过原生或 Vue 方式接入 Demo 并看到首条有效数据。
3. 平台展示首屏、秒开率、Web Vitals、长任务、网络、资源、内存能力状态和异常。
4. 用户能按时间、环境、版本、页面、设备和网络筛选数据。
5. 无效数据被正确丢弃；缺失必要字段按规则推导，失败后丢弃；系统失败进入死信。
6. 平台可查看接收率、丢弃率、推导成功率、积压、死信和隔离量。
7. 秒开率、卡顿率、异常率和分位数通过已知测试数据集验证计算正确。
8. 用户能配置 Webhook/邮件告警，并收到触发及恢复通知。
9. 诊断结果能展示影响范围、相关版本、数据证据和可执行建议。
10. SDK、平台或网络失败不影响 Demo 的核心业务操作。
11. P0 功能通过功能、契约、兼容、端到端、数据质量、安全和容量测试。
12. 部署、接入、指标、告警和异常帮助文档完整可用。
