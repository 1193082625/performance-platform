# 性能指标与数据口径

- **文档状态**：草案
- **当前开发版本**：v0.2（Web Vitals、采样与实验性内存）
- **完整适用版本**：Web MVP 1.0
- **关联文档**：[PRD](./product-requirements.md) · [总体架构设计](../plans/2026-08-23-open-performance-platform-design.md)

## 1. 文档目的

统一 SDK、数据接入、计算引擎、控制台、告警和测试使用的指标定义，避免同一指标在不同模块中出现不同结果。

每个正式指标必须明确：

- 适用平台和数据来源。
- 计算公式、单位、有效分子和有效分母。
- 去重键、时间口径和聚合维度。
- 缺失、推导、异常值、采样和兼容性处理。
- 指标版本、告警建议和验收数据集。

本文默认时间单位为毫秒（ms），比例在存储层使用 `[0,1]`，展示层格式化为百分比。

### 1.1 v0.2 指标范围

v0.2 生产以下指标：

| 指标 | 口径 |
|---|---|
| FP | `first-paint` PerformanceEntry 的 `startTime` |
| FCP | `first-contentful-paint` PerformanceEntry 的 `startTime` |
| LCP | 当前页面生命周期内最后一个有效候选值 |
| CLS | `web-vitals` 最大会话窗口布局偏移分数 |
| INP | `web-vitals` 计算的页面交互延迟代表值 |
| JS 堆内存 | Chromium `performance.memory` 的 used、total 和 limit 快照 |
| 样本量 | 查询范围内各指标的有效事件数 |
| 平均值 | 有效指标值之和除以有效样本量 |
| P50/P75/P90 | PostgreSQL `percentile_cont` 计算的连续分位数 |
| 时间趋势 | 按查询粒度分桶后的样本量、平均值、P50、P75、P90 |

v0.2 不计算秒开率、长任务、网络、资源和异常。FP/FCP 或 Web Vital 缺失时不推导、不写入 `0`，只是不产生对应事件。内存属于实验性能力，不支持时不产生事件。

## 2. 核心概念

### 2.1 事件时间

| 字段 | 含义 | 用途 |
|---|---|---|
| `clientTime` | 客户端事件发生时间 | 业务时间线和窗口归属 |
| `serverReceivedAt` | 网关收到事件的时间 | 延迟、时钟校正和审计 |
| `processedAt` | 完成标准化的时间 | 处理延迟和积压监控 |

统计优先使用校正后的 `clientTime`。当客户端时间无法可靠校正时，依指标规则使用 `serverReceivedAt` 或丢弃事件，不得静默替换。

### 2.2 用户、设备、会话和页面访问

- **用户 `userId`**：业务显式设置并经过脱敏的稳定标识；缺失时不推导。
- **匿名设备 `deviceId`**：SDK 生成的匿名标识，受存储与隐私策略限制。
- **会话 `sessionId`**：一段连续使用过程。默认 30 分钟无活动后创建新会话。
- **页面访问 `viewId`**：一次页面打开或 SPA 路由进入。每次有效导航必须生成新值。
- **事件 `eventId`**：全局唯一事件标识，用于幂等去重。

同一浏览器中 `userId`、`deviceId` 和 `sessionId` 具有不同含义，控制台不得统一显示成“用户数”。

### 2.3 有效事件

满足以下条件的事件才可参与正式指标：

1. 通过协议、类型、范围和时间关系校验。
2. 事件未重复、未过期且不是 SDK 递归上报。
3. 指标所需必要字段存在，或可以通过 `exact` 规则精确推导。
4. 对应运行环境声明支持该指标。
5. 未命中机器人、内部流量或项目排除规则。

`estimated` 近似数据默认只用于诊断，不进入核心 SLA 指标。控制台若展示估算数据，必须单独标记。

### 2.4 有效页面访问

有效页面访问同时满足：

- 具有有效 `appId`、`environment`、`viewId`、`route` 和开始时间。
- 页面不是预渲染、后台预加载或被项目规则排除。
- 页面至少进入过可见状态；始终在后台的页面不计入体验指标。
- SDK 初始化时间未晚于对应指标的可采集窗口；否则只参与仍然有效的指标。

### 2.5 指标状态

每个可选指标必须记录状态：

| 状态 | 含义 | 是否参与统计 |
|---|---|---|
| `measured` | 原生能力直接测量 | 是 |
| `derived_exact` | 由确定字段精确推导 | 是 |
| `estimated` | 近似估算 | 默认否 |
| `unavailable` | 当前运行环境不支持 | 否 |
| `invalid` | 数据存在但校验失败 | 否，并记录丢弃原因 |
| `missing` | 应提供但未提供 | 否，并记录质量问题 |

## 3. 通用统计规则

### 3.1 计数与去重

| 指标 | 默认去重键 |
|---|---|
| 事件数 | `eventId` |
| 页面访问量 PV | `viewId` |
| 会话数 | `sessionId` |
| 用户数 UV | 优先 `userId`，否则单独统计匿名 `deviceId` |
| 受影响页面访问 | `viewId` |
| 受影响会话 | `sessionId` |
| 受影响用户 | `userId`，不使用会话数代替 |

跨日会话按会话开始时间归属会话数；会话内事件仍按各自事件时间进入时序窗口。

### 3.2 时间窗口

- 原始事件按事件时间写入对应分区。
- 默认预聚合粒度为 1 分钟、1 小时和 1 天。
- 控制台根据查询范围选择最细且成本合理的粒度。
- 项目时区只影响展示和自然日边界，存储统一使用 UTC。
- 默认允许事件迟到 10 分钟；窗口先输出临时结果，迟到窗口关闭后转为稳定结果。
- 超过迟到窗口的数据进入明细，但不自动修改已稳定聚合；管理员可触发受控重算。

### 3.3 分位数

- 正式展示 P50、P75、P90、P99，不用平均值代替用户体验分布。
- 小样本少于 20 时不展示 P99；少于 5 时只展示样本，不给出趋势结论。
- ClickHouse 预聚合使用可合并分位数状态，算法和参数写入 `metricVersion`。
- 同一图表内不同时间点必须使用相同分位数算法。

### 3.4 采样

每条事件必须携带有效采样率 `sampleRate`，范围 `(0,1]`。

- 确定性会话采样下，计数估算权重为 `1 / sampleRate`。
- 比例指标的分子、分母必须使用相同采样策略和权重。
- 无法确定采样率的事件不得进行总体量放大，只能展示采样数据。
- 错误事件和性能事件采用不同采样率时，不得直接计算跨事件比例。
- 控制台必须展示“已采样”状态和当前有效样本量。

### 3.5 缺失与推导

处理顺序：

```text
检查必要字段 → exact 推导 → 校验推导结果
→ 成功则记录规则 → 失败则丢弃该指标或整条事件
```

示例：

```text
duration 缺失 + startTime/endTime 有效
→ duration = endTime - startTime
→ status = derived_exact
```

必要字段推导失败时丢弃整条依赖该字段的原子事件；非必要指标推导失败时只丢弃该指标。

### 3.6 异常值

- 负耗时、结束时间早于开始时间、比例超出 `[0,1]`：无效。
- 超过项目设置的最大合理值：标记异常值，不参与核心统计，保留受控诊断样本。
- 不使用任意截尾方式美化数据；任何截断规则必须有版本和原因。
- `0` 只有在业务含义允许时才是合法值，不能代表缺失或不支持。

## 4. 流量与覆盖指标

### 4.1 页面访问量 PV

| 项目 | 定义 |
|---|---|
| 指标 ID | `web.page_views` |
| 公式 | 有效时间范围内去重 `viewId` 数 |
| 单位 | 次 |
| 必要字段 | `viewId`、`route`、事件时间 |
| 默认维度 | 应用、环境、版本、路由 |

同一次 SPA 路由重新进入生成新 `viewId`；组件重新渲染不产生新页面访问。

### 4.2 会话数

| 项目 | 定义 |
|---|---|
| 指标 ID | `web.sessions` |
| 公式 | 去重 `sessionId` 数 |
| 单位 | 个 |
| 默认超时 | 30 分钟无活动，可按应用覆盖 |

### 4.3 活跃用户数

分别展示：

- `known_users`：去重 `userId`。
- `anonymous_devices`：没有 `userId` 的去重 `deviceId`。

二者默认不相加为“精确用户数”，避免同一用户跨设备或登录前后重复。

### 4.4 SDK 覆盖率

```text
SDK 覆盖率 = 成功产生有效 page_view 的业务页面访问数
            / 业务侧提供的总页面访问数
```

该指标需要业务侧独立总量才能计算。平台自身没有独立分母时只展示有效采集量，不宣称覆盖率。

## 5. 页面加载与渲染指标

### 5.1 页面加载耗时

| 项目 | 定义 |
|---|---|
| 指标 ID | `web.navigation.load_duration` |
| 数据来源 | Navigation Timing |
| 公式 | `loadEventEnd - startTime` |
| 必要条件 | 两个时间点有效且页面加载事件已完成 |
| 单位 | ms |

SPA 客户端路由切换不使用该指标，应使用自定义路由渲染指标。

### 5.2 DOM 可交互准备时间

| 指标 ID | 公式 |
|---|---|
| `web.navigation.dom_interactive` | `domInteractive - startTime` |
| `web.navigation.dom_content_loaded` | `domContentLoadedEventEnd - startTime` |

仅用于导航分析，不将其直接等同于首屏完成。

### 5.3 首屏时间 FST

| 项目 | 定义 |
|---|---|
| 指标 ID | `web.render.first_screen_time` |
| 含义 | 首个视口内主要内容达到稳定可见状态的时间 |
| 数据来源 | Paint/Resource/DOM 观察与首屏算法 |
| 单位 | ms |
| 状态 | `measured` 或 `estimated` |

首屏算法必须单独版本化。MVP 中估算首屏不得和原生 LCP 混为同一指标；控制台同时展示算法版本和能力状态。

### 5.4 秒开率

| 项目 | 定义 |
|---|---|
| 指标 ID | `web.render.instant_rate` |
| 默认阈值 | 1,000 ms，可按项目配置 |
| 分子 | 首屏时间小于等于阈值的有效页面访问数 |
| 分母 | 成功采集有效首屏时间的页面访问数 |
| 公式 | `instantViews / validFirstScreenViews` |

不支持首屏采集、采集过晚、后台预加载、首屏状态为 `estimated` 的页面默认不进入核心秒开率。

### 5.5 First Contentful Paint

| 项目 | 定义 |
|---|---|
| 指标 ID | `web.vitals.fcp` |
| 数据来源 | Paint Timing |
| 公式 | FCP entry 的 `startTime` |
| 单位 | ms |

MVP 0.1 同时支持 First Paint：

| 项目 | 定义 |
|---|---|
| 指标 ID | `web.paint.fp` |
| 数据来源 | Paint Timing 的 `first-paint` entry |
| 公式 | entry 的 `startTime` |
| 单位 | ms |
| 有效条件 | 数值有限且大于等于 0 |

FCP 在 MVP 0.1 使用指标 ID `web.paint.fcp`；两者独立统计，缺少 FP 或 FCP 不影响另一指标入库。

### 5.6 Largest Contentful Paint

| 项目 | 定义 |
|---|---|
| 指标 ID | `web.vitals.lcp` |
| 数据来源 | Largest Contentful Paint API |
| 取值 | 页面生命周期内最后一个有效 LCP 候选值 |
| 单位 | ms |

页面隐藏、冻结或用户交互时按 SDK 规则固化当前值；无有效候选时为 `missing`，不能使用 FCP 代替。

### 5.7 Cumulative Layout Shift

| 项目 | 定义 |
|---|---|
| 指标 ID | `web.vitals.cls` |
| 数据来源 | Layout Instability API |
| 取值 | 最大会话窗口内布局偏移分数之和 |
| 单位 | 无量纲 |

由近期用户输入导致的偏移按标准规则排除。算法版本变化必须提升指标版本。

### 5.8 Interaction to Next Paint

| 项目 | 定义 |
|---|---|
| 指标 ID | `web.vitals.inp` |
| 数据来源 | Event Timing API |
| 取值 | 页面生命周期内按标准算法得到的交互延迟代表值 |
| 单位 | ms |

没有发生有效交互的页面不进入 INP 分母，状态记为 `missing`，不记为 0。

### 5.9 Web Vitals 等级

等级阈值不硬编码在查询逻辑中，存储为可版本化指标配置。默认配置应跟随项目发布时采用的公开标准，并在文档中记录来源日期。控制台必须允许查看原始值，等级只作为辅助标签。

## 6. 流畅度与卡顿指标

### 6.1 长任务

| 项目 | 定义 |
|---|---|
| 指标 ID | `web.long_task.duration` |
| 数据来源 | Long Tasks API |
| 默认条件 | 单个主线程任务持续时间大于等于 50 ms |
| 单位 | ms |

不支持 Long Tasks API 时的定时器漂移只能产生 `estimated` 卡顿事件，不与原生长任务合并计算。

### 6.2 卡顿页面访问

满足以下任一规则的有效页面访问被记为卡顿页面访问：

- 至少发生一次有效长任务。
- 命中项目配置的严重卡顿规则。

### 6.3 卡顿率

```text
卡顿率 = 至少发生一次有效卡顿的去重 viewId 数
        / 支持且成功完成卡顿观察的有效 viewId 数
```

指标 ID：`web.freeze.view_rate`。页面生命周期尚未结束时可展示临时结果，必须标记为进行中。

### 6.4 严重卡顿率

默认严重卡顿定义为单次长任务持续时间大于等于 200 ms，阈值可配置并版本化。

```text
严重卡顿率 = 存在严重长任务的有效 viewId 数
              / 有效卡顿观察 viewId 数
```

### 6.5 长任务阻塞时间

```text
阻塞时间 = Σ max(longTaskDuration - 50, 0)
```

按页面访问聚合后展示 P75/P90/P99。该指标用于衡量影响程度，不用长任务次数代替。

## 7. 网络请求指标

### 7.1 请求耗时

| 项目 | 定义 |
|---|---|
| 指标 ID | `web.request.duration` |
| 公式 | 请求结束时间减请求开始时间 |
| 单位 | ms |
| 适用 | 被允许采集的 fetch/XHR |

被主动取消的请求单独标记为 `cancelled`，不默认计入成功或失败。

### 7.2 请求成功

默认规则：

- HTTP 200～399：成功。
- HTTP 400～599：失败。
- 网络错误、超时：失败。
- 主动取消：取消，不进入默认成功率分母。
- 业务码成功规则：项目显式配置后单独计算业务成功率。

### 7.3 请求成功率

```text
HTTP 请求成功率 = 成功请求数 /（成功请求数 + 失败请求数）
```

按请求事件计数，不按用户或会话去重。重试产生的每次实际请求分别计数，另提供逻辑请求标识用于重试分析。

### 7.4 慢请求率

```text
慢请求率 = 耗时超过接口规则阈值的完成请求数
            / 具有有效耗时的完成请求数
```

默认阈值为 1,000 ms，支持按标准化后的请求方法和 URL 模式配置接口级覆盖值。匹配优先级为“更具体接口规则 → 通用接口规则 → 应用默认值”；同级冲突按显式优先级处理，未命中时回退到 1,000 ms。阈值和匹配规则变化必须记录规则版本。

## 8. 静态资源指标

### 8.1 资源加载耗时

指标 ID：`web.resource.duration`，使用 Resource Timing 的有效 `duration`，按脚本、样式、图片、字体和其他资源分类。

### 8.2 资源失败率

```text
资源失败率 = 资源加载失败事件数
              /（成功加载资源数 + 资源加载失败数）
```

如果跨域限制导致资源成功状态无法确定，则该资源不进入成功率分母，并标记能力限制。

### 8.3 慢资源贡献度

```text
慢资源贡献度 = 某资源模式的阻塞/加载耗时总量
                / 当前分析范围内资源耗时总量
```

该指标用于诊断排序，不等同于因果关系。控制台必须同时展示样本量和相关页面。

## 9. 异常与稳定性指标

### 9.1 异常事件

MVP 包含：JavaScript Error、未处理 Promise、资源失败和接口失败。每条异常生成稳定 `fingerprint`，指纹算法和版本必须记录。

### 9.2 异常页面率

```text
异常页面率 = 至少发生一次目标异常的去重 viewId 数
              / 有效页面访问 viewId 数
```

筛选特定异常类型时，分子只包含该类型，分母保持所有具有对应采集能力的有效页面访问。

### 9.3 异常会话率

```text
异常会话率 = 至少发生一次目标异常的去重 sessionId 数
              / 有效 sessionId 数
```

### 9.4 受影响用户数

仅统计具有 `userId` 的去重用户；匿名设备数独立展示，不能合并为精确用户数。

### 9.5 新增异常

在当前版本首次出现，且在配置的历史基线窗口中不存在同一指纹的异常。默认基线可设为前 7 天和最近 3 个有效版本，具体规则必须版本化。

### 9.6 异常事件率

异常事件数除以页面访问数容易被单页面异常风暴放大，因此只作为辅助强度指标，核心稳定性优先使用异常页面率和异常会话率。

## 10. 内存指标

Web 内存能力仅在部分运行环境可用，所有指标标记为实验性。

### 10.1 堆内存使用量

| 指标 ID | 含义 |
|---|---|
| `web.memory.used_heap` | 当前已使用 JS 堆内存，单位 byte |
| `web.memory.total_heap` | 当前分配堆内存，单位 byte |
| `web.memory.heap_limit` | JS 堆内存上限，单位 byte |

### 10.2 堆内存使用率

```text
堆内存使用率 = used_heap / heap_limit
```

只有两个字段都有效且大于 0 时计算。

### 10.3 内存告警

默认在使用率大于 80% 且连续 3 个有效采样点后触发，支持按应用或告警规则覆盖。单次峰值默认不触发持续性告警。

### 10.4 疑似内存增长

使用同一页面访问或同类长会话中的采样序列计算趋势。只有采样点数、观察时长和增长幅度同时达到配置要求时输出“疑似增长”，不得直接断言内存泄漏。

## 11. 数据质量指标

### 11.1 接收量

网关成功解包并进入接入处理层的原始事件数。

### 11.2 标准事件数

通过校验、推导、清洗和去重后进入事件队列的事件数。

### 11.3 有效接收率

```text
有效接收率 = 标准事件数 / 进入接入处理层的原始事件数
```

主动限流发生在进入处理层之前，应单独展示 `rate_limited_total`，不能从分母中隐去。

### 11.4 丢弃率

```text
丢弃率 = 业务无效且不可恢复的事件数
          / 进入接入处理层的原始事件数
```

原因维度至少包含 Schema 错误、必要字段缺失、推导失败、范围无效、时间无效、重复、过期、超限和递归上报。

### 11.5 推导成功率

```text
推导成功率 = 成功推导必要字段的事件数
              / 需要推导必要字段的事件数
```

`exact` 和 `estimated` 必须分开统计。

### 11.6 死信量和隔离量

- 死信量：由于系统暂时性失败而未完成处理、可重放的事件数。
- 隔离量：协议暂不识别、等待人工或版本处理的事件数。

两者都不是业务无效数据，不计入丢弃率，但必须监控积压年龄。

### 11.7 端到端处理延迟

```text
处理延迟 = 聚合结果可查询时间 - serverReceivedAt
```

展示 P50/P95/P99，并区分接入、队列、计算和存储阶段延迟。

## 12. 版本回归指标

### 12.1 对比前提

版本对比需要：

- 相同应用、环境、指标版本和计算规则。
- 尽量保持页面、设备、网络和地区分布一致。
- 当前版本与基线版本均达到最小样本量。

### 12.2 相对变化率

```text
相对变化率 =（当前值 - 基线值）/ 基线值
```

对于“越高越好”的比例指标，负变化代表退化；对于耗时、卡顿率和异常率，正变化代表退化。基线为 0 时不计算相对变化，只展示绝对差。

### 12.3 回归判定

同时满足最小样本量、绝对变化阈值和相对变化阈值后才判定回归。MVP 可先使用规则判断，后续再引入统计显著性检验。

## 13. 告警口径

每条告警规则必须包含：指标 ID、指标版本、比较符、阈值、聚合窗口、连续窗口数、最小样本量、过滤维度和恢复条件。

示例：

```text
应用：商城 Web / production
指标：web.freeze.view_rate@v1
条件：5 分钟卡顿率 > 5%
持续：连续 3 个窗口
最小样本：每窗口 100 个有效 viewId
恢复：连续 2 个窗口 <= 5%
```

数据延迟、窗口未稳定或样本不足时保持 `insufficient_data`，不得误判正常或告警。

## 14. 默认分析维度

| 维度 | 说明 |
|---|---|
| 应用/环境 | `appId`、production/staging 等 |
| 版本 | 业务发布版本，不使用 SDK 版本代替 |
| 页面 | 标准化 route，去除动态 ID 和敏感参数 |
| 浏览器/系统 | 标准化名称和主版本 |
| 设备 | desktop/mobile/tablet 等分类 |
| 网络 | 有能力时记录网络类型和有效连接类型 |
| 地区 | 服务端按合规配置推导到允许的粒度 |
| SDK | SDK 名称、版本和能力矩阵 |
| 数据状态 | measured/derived/estimated/unavailable |

高基数字段不得直接作为默认聚合维度。完整 URL、用户 ID、错误消息和自定义标签需要权限、限额与查询保护。

## 15. 指标版本管理

以下变化必须提升 `metricVersion`：

- 公式、阈值默认值或有效分母改变。
- 去重、异常值、采样权重或迟到数据规则改变。
- 浏览器算法、首屏算法、异常指纹算法改变。
- 聚合算法精度发生会影响结果的变化。

控制台默认不把不同版本的指标连成同一趋势；若提供迁移换算，必须明确标注。

## 16. 验收要求

每个 P0 指标上线前必须具备：

1. 固定输入事件和预期结果的黄金数据集。
2. SDK 原始值与浏览器测试页面的对照验证。
3. 接入层对缺失、推导、无效、重复和超期数据的测试。
4. 分钟、小时、天聚合一致性测试。
5. 采样、乱序、迟到、时区和重算测试。
6. 查询 API 与控制台展示值一致性测试。
7. 指标状态、有效样本量和口径说明在控制台可见。
8. 指标 ID、公式和版本写入公开文档。
